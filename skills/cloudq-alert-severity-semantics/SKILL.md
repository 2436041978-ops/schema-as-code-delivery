# 告警语义分级与处置边界

## 适用范围与证据边界

cloudq.alert.query / cloudq.graph.trace / cloudq.metric.query
证据仅来自「告警内容 + 拓扑上下文 + 指标时序」三类。
本 Skill 不执行根因定位——收敛与根因定位由 triaging 类 Skill 完成，
本 Skill 消费其输出，对"告警如何向人表达"做语义分级与措辞约束。

## 语义分级

按"用户承受的后果"将告警分为四级，不按触发来源、不按指标数值大小定级：

- fatal（致命）：服务不可用或数据可能丢失，用户必须立即行动
- transient（瞬时）：临时抖动或短暂过载，系统可自动恢复，用户无需行动
- retryable（可重试）：限流或配额触顶，等待后可恢复，用户需等待或升级
- degraded（降级）：部分功能异常，核心功能可用，用户可继续使用但需知晓

分级依据不足时输出"未知"并标注待验证，不编造置信度。

## 用户行动

每级告警必须携带对应的处置语义（仅建议，不执行）：

- fatal：立即处理 + 恢复路径 + 影响面说明
- transient：无需操作 + 自动恢复预期
- retryable：等待倒计时 + 升级/扩容路径
- degraded：继续使用 + 功能受限说明

## 措辞约束

关键术语禁止被同义词替换，替换即拦截（完整清单见 references/severity-levels.md）：

- Critical → 禁止替换为"严重""紧急""很重要"
- Warning → 禁止替换为"注意""提醒""提示"
- fatal → 禁止替换为"出了点小问题""服务异常""请稍后重试"

判定标准：替换后用户的紧急程度判断发生变化，即视为降级。

## 不可变边界

- 只读诊断不做变更，所有处置建议需用户确认后执行
- fatal 级处置必须二次确认
- 禁止对 transient 级告警给出重启、删除、回滚等破坏性处置建议
- 术语防火墙不可绕过，禁止以"更友好"为由替换已注册的关键术语

## LLM约束

必须型：
- fatal 级文案必须包含"不可恢复"或"立即处理"语义，必须提供恢复路径
- transient 级文案必须说明预计恢复时间
- retryable 级文案必须显示剩余等待时间，必须提供升级路径
- degraded 级文案必须说明哪些功能仍然可用

禁止型：
- 禁止 fatal 级仅显示"服务异常"等模糊文案
- 禁止 transient 级使用红色或紧急措辞
- 禁止 degraded 级仅显示技术错误码
- 禁止以指标数值大小直接定级

限制型：
- 告警定级以"用户承受的后果"为准——CPU 95% 可能是 transient（自动扩容中），
  连接池耗尽可能是 fatal
- 置信度必须说明"为什么不是更高"；不确定就标注"待验证"，不编造证据链
