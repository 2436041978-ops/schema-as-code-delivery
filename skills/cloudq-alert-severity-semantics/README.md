# cloudq-alert-severity-semantics（告警语义分级与处置边界）

> 告警收敛与根因定位之后，还差一步：这条告警是什么级别、用什么措辞、给什么处置建议。
> 本 Skill 把这一层判断逻辑写成 CloudQ 可调用的能力资产。

## 这是什么

按"用户承受的后果"将告警分为 fatal / transient / retryable / degraded 四级，措辞权重与级别绑定，术语防火墙拦截同义词降级，处置权完整保留在人手里。与官方示范 cloudq-alert-triaging 上下游互补：triaging 管"告警之间是什么关系"（收敛、根因定位），本 Skill 管"告警和人之间是什么关系"（级别、措辞、处置语义）。

## 怎么挂载

把本目录放入 CloudQ 的 Skill 目录，确认 SKILL.md 的 description 触发词覆盖你的告警场景（「告警分级」「告警文案」「处置建议」「告警语义」「这条告警严重吗」）。

## 怎么验证有效（三步基线对比）

1. 取一批历史告警，用 `assets/severity-checklist.md` 人工走查，标出当前文案里的降级替换（如 Critical 被写成"严重"、fatal 被写成"请稍后重试"）——这一步产出基线；
2. 用自然语言唤起 Skill 对同一批告警做分级与文案改写，与基线对比；
3. 差异即 Skill 的价值回执；误拦与漏拦按消费侧反馈回到契约评审队列。

验收标准只有一句话：有没有 Skill，告警的级别与措辞差异可复现。

## 信源契约版本

- ERR-001 错误状态后果差异未分级 契约 v1.2.0（分级骨架：四级 + 每级用户行动）
- ALR-001 告警文案语义降级 契约 v1.0.0（措辞约束：术语防火墙清单）

正文措辞的严格程度与契约一致——"禁止"不允许写成"建议"。改约束，改契约，走评审；SKILL.md 随版本重编译，不手改。

## 边界声明

不执行根因定位（triaging 类 Skill 的职责）；不保证定级完全准确——依据不足时输出"未知"，不编造置信度；防火墙拦截的是"已注册术语的降级替换"，未注册的新术语走契约评审注册后再纳入。量化收益均为数据模型推演口径，待生产数据校准。
